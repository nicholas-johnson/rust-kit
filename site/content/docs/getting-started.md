This page takes you from an empty directory to a running server with an interactive page. You set the crate up by hand: it is five small files, and seeing each one makes the rest of the docs easier to follow.

> [!TIP]
> In a hurry? `rustkit new my-app` writes a working app with a static page, a counter, server data, a layout, a component and tests. Then `cd my-app` and run `rustkit dev`. See [CLI](/docs/cli/#rustkit-new).

## Prerequisites

- A Rust toolchain that supports **edition 2024** (Rust 1.85 or newer). Check with `rustc --version`.
- Network access to GitHub. The crates are not on crates.io; Cargo fetches them from the repository.
- A browser. No Node.js, npm, or bundler is needed at any point.

## 1. Create the crate

```bash
cargo new hello-rustkit
cd hello-rustkit
mkdir -p src/routes
```

## 2. Add dependencies

Replace `Cargo.toml` with:

```toml title=Cargo.toml
[package]
name = "hello-rustkit"
version = "0.1.0"
edition = "2024"

[dependencies]
rustkit = { git = "https://github.com/nicholas-johnson/rust-kit" }
axum = "0.8"
tokio = { version = "1", features = ["full"] }
serde = { version = "1", features = ["derive"] }

[build-dependencies]
rustkit-compiler = { git = "https://github.com/nicholas-johnson/rust-kit" }
```

Why each one:

| Crate | Used for |
| --- | --- |
| `rustkit` | The runtime: `App`, `RequestContext`, sessions, errors. |
| `rustkit-compiler` | Runs in `build.rs` and compiles your `.rk` pages. It is a build dependency only. |
| `axum` | `rustkit` builds an `axum::Router`; you call `axum::serve` yourself. |
| `tokio` | The async runtime and the TCP listener. |
| `serde` | Your data source views derive `Serialize`. |

> [!TIP]
> Cargo records the exact commit in `Cargo.lock`. To pin it explicitly, add `rev = "<commit>"` to both Git dependencies.

## 3. Add the build script

Create `build.rs` next to `Cargo.toml`:

```rust title=build.rs
fn main() {
    rustkit_compiler::build_script();
}
```

`build_script()` compiles every `.rk` file under `src/routes`, writes the generated Rust and the browser assets into Cargo's `OUT_DIR`, and asks Cargo to rerun it when anything in `src/routes` changes. If a page has an error, the build stops and prints a diagnostic that points at the line in your `.rk` file.

The generated code makes two assumptions about your crate, and they are fixed in this release:

- there is a type at `crate::AppState` (your application state), and
- there is a module at `crate::sources` (your data source resolvers).

## 4. Write `main.rs`

Replace `src/main.rs` with:

```rust title=src/main.rs
/// Shared application state. Resolvers and actions reach it through the
/// request context, e.g. `ctx.some_client`.
pub struct AppState {}

/// Data source resolvers. Empty for now.
pub mod sources {}

/// The compiled pages, generated by build.rs.
mod generated {
    include!(concat!(env!("OUT_DIR"), "/rustkit_generated.rs"));
}

#[tokio::main]
async fn main() {
    let app = rustkit::App::new(generated::manifest(), AppState {})
        // Plain-HTTP local development only. See the note below.
        .secure_cookies(false);
    let router = app.into_router().await.expect("prerender failed");

    let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
    println!("listening on http://127.0.0.1:3000");
    axum::serve(listener, router).await.unwrap();
}
```

What is going on:

- `include!` pulls in the generated file. It defines one module per page and a `manifest()` function that lists every route, asset, and browser-loadable source.
- `App::new(manifest, state)` wraps the manifest and your state. Later you will chain `.action("/path", handler)` here to register form handlers; see [Form actions](/docs/form-actions/).
- `into_router()` renders any prerendered pages once and returns an ordinary `axum::Router`. You can nest it, add middleware, or serve it however you like.

> [!WARNING]
> Session cookies carry the `Secure` attribute by default, and some browsers will not send a `Secure` cookie over plain `http://`. That would break sign-in and CSRF-checked forms locally. `.secure_cookies(false)` turns the attribute off. Leave it on (remove the line, or decide based on the bind address as the demo does) anywhere that serves over HTTPS.

## 5. Write your first page

Create `src/routes/index.rk`. A file called `index.rk` maps to `/`.

```rk title=index.rk
<script>
  let count = $state(0);
</script>

<title>Hello, Rust-kit</title>

<h1>Hello from Rust-kit</h1>
<p>This heading was rendered by Rust before any JavaScript ran.</p>
<button onclick={() => count = count + 1}>Clicked {count} times</button>
```

## 6. Run it

```bash
cargo run
```

The first build downloads and compiles dependencies, so give it a minute. Then open <http://127.0.0.1:3000>.

Things to try:

- **View the page source.** The heading and `Clicked 0 times` are in the raw HTML. Around the `0` you will see `<!--rk:b4-->` and `<!--/rk:b4-->`. Those comments mark a *block*, the smallest region the browser re-renders when `count` changes. See [Blocks and updates](/docs/blocks-and-updates/).
- **Click the button.** Only the number changes.
- **Disable JavaScript and reload.** The page still reads correctly; only the button stops working.
- **Check the response headers.** Every request-rendered page has a `Server-Timing` header that splits time spent waiting on data sources from time spent rendering.

## 7. Add a second, static page

Create `src/routes/about.rk`:

```rk title=about.rk
<script context="module">
  export const prerender = true;
</script>

<title>About</title>

<h1>About</h1>
<p>This page has no state and no handlers, so it ships no JavaScript.</p>
<p><a href="/">Back home</a></p>

<style>
  body { font-family: system-ui, sans-serif; max-width: 40rem; margin: 2rem auto; }
</style>
```

Run `cargo run` again and open `/about`. Because of `prerender = true`, Rust renders this page once at startup and serves the same bytes to everyone with `Cache-Control: public, max-age=300`. The `<style>` block becomes a content-hashed stylesheet linked from the page head. See [Pages and routes](/docs/pages-and-routes/) and [Styling](/docs/styling/).

## 8. Read data from Rust

Pages get data from **sources**: async functions in `crate::sources` that take the request context and return a serializable view. Replace the empty `sources` module in `main.rs` with:

```rust title=src/main.rs
pub mod sources {
    use rustkit::Error;
    use serde::Serialize;

    type Ctx = rustkit::RequestContext<crate::AppState>;

    #[derive(Serialize)]
    #[serde(rename_all = "camelCase")]
    pub struct ServerInfo {
        pub greeting: String,
        pub page_count: u32,
    }

    pub async fn server_info(_ctx: &Ctx) -> Result<ServerInfo, Error> {
        Ok(ServerInfo { greeting: "Hello from a resolver".into(), page_count: 2 })
    }
}
```

Then use it from a page, for example a new `src/routes/info.rk`:

```rk title=info.rk
<script>
  import { server_info } from "$sources";
</script>

<title>Server info</title>

<DataSource source={server_info} load="server" let:data>
  <h1>{data.greeting}</h1>
  <p>This site has {data.pageCount} pages.</p>
</DataSource>
```

> [!IMPORTANT]
> The import name must match the Rust function name exactly, because the generated code calls `crate::sources::server_info(ctx)`. Field names work differently: templates read the **camelCase** JSON names (`data.pageCount`), which is why views use `#[serde(rename_all = "camelCase")]`. The compiler maps them back to the Rust fields (`page_count`) when it generates the renderer.

Rebuild and open `/info`. To learn more, read [Data sources](/docs/data-sources/) and [Loading on the server](/docs/server-loading/).

## Run the bundled demo

The repository includes `examples/account-demo`, the reference app from the design proposal: a static article and a signed-in account page with a profile editor and an activity feed loaded in the browser.

```bash
git clone https://github.com/nicholas-johnson/rust-kit
cd rust-kit
cargo run -p account-demo -- serve 127.0.0.1:3000
```

Sign in at `/login` as Alice or Bob (demo accounts, no password). The demo imitates a 25 ms round trip to an accounts service, which makes the `Server-Timing` numbers more interesting.

The demo also has a `build` command that writes the prerendered routes and assets to a directory and prints JavaScript and CSS bytes per route:

```bash
cargo run -p account-demo -- build dist
```

Both commands are implemented in the demo's own `main.rs`, not by the framework; see [CLI](/docs/cli/).
